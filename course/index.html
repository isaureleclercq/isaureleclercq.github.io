Lesson 01 / 08 · Your starting point · ~20 min

A few files. A whole website.

A website starts as a folder. In this lesson, you’ll learn what each file does, open the portfolio on your computer, and make your first small change.

  • Understand the file structure
  • Run a local server
  • Make your first edit

Meet the three building blocks

HTML describes the content: headings, paragraphs, navigation, and images. CSS decides how that content looks and fits together. JavaScript adds behavior, including loading the introduction and project cards.

This portfolio is a static website. A server sends its files to your browser, and the browser displays them. There is no database, login, or build step. You can learn how the whole thing works by opening a handful of files.

HTML · structure+CSS · appearance+JS · behavior

A map of this project

index.htmlThe page: navigation, introduction, project area, About section, and footer.
styles.cssTypography, spacing, and layouts for different screens.
themes.cssShared palettes and typography for all four designs.
theme.jsReads site.json and applies the selected design on every page.
script.jsBuilds the project cards and applies the homepage copy.
site.jsonYour selected design, name, introduction, and About text.
projects.jsonA list of your projects. An empty list looks like [].
assets/Images and the small browser-tab icon, called a favicon.

Open the project locally

You need a browser, a plain-text code editor, and Python 3. The local environment for this project already has Python. Open the project folder in your editor. In a terminal, go to the same folder and start a server. Replace the example path below with your project folder:

Terminal · macOS
cd "/path/to/your/portfolio"
python3 -m http.server 8000 --bind 127.0.0.1

Visit localhost:8000. If this course is already running there, the server is already started. Keep its terminal open while working. To stop a server you started, press Ctrl + C in that terminal.

Why a server? Double-clicking an HTML file opens a file:// URL. Browsers restrict requests from these pages, so fetching the JSON can fail. A local http:// address lets the files work together.

On another computer, replace the folder path with your own. If port 8000 is busy, reuse the existing preview or start on port 8001 and visit http://localhost:8001. On Windows, py -m http.server 8000 --bind 127.0.0.1 is a common equivalent when Python is installed.

Make the edit → save → refresh loop

Open site.json and find "intro". Change only the words inside its quotation marks. Save the file and refresh the portfolio tab. You should see your new introduction. This server does not automatically refresh the browser.

Keep this course open in another tab. For bigger experiments, make a copy of the project folder first. You can also use the course’s workbench without changing the portfolio files.

Lesson 02 / 08 · HTML foundations · ~30 min

Start with meaning.

Before choosing a color or a font, give the page a clear structure. HTML tells the browser what each piece of content means.

  • Read HTML elements
  • Use semantic sections
  • Connect links and IDs

Read an HTML element

An element usually has an opening tag, some content, and a closing tag. In <h1>Hello, I’m Isaure.</h1>, the tags make the text a heading. An attribute gives an element extra information, such as the destination of a link.

HTML · a link
<a href="#about">A little about me</a>

a means anchor, href is its destination, and the text between the tags is the link label. A destination starting with # points to an element with a matching id on the same page.

Build the document skeleton

The head contains information for the browser. The body contains the page people see. The title appears in the browser tab, while the viewport setting lets the layout use a phone’s actual screen width. This is a small complete example, not a replacement for your existing file:

index.html · minimal example
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>My portfolio</title>
    <link rel="stylesheet" href="styles.css">
    <script src="script.js" defer></script>
  </head>
  <body>
    <header><nav><a href="#work">Work</a></nav></header>
    <main>
      <h1>Hello, I’m Isaure.</h1>
      <section id="work">
        <h2>Selected work</h2>
        <p>A collection of things I’m making.</p>
      </section>
    </main>
    <footer>Made with curiosity.</footer>
  </body>
</html>

Choose elements by their purpose

header introduces the page; nav groups its main navigation links; main contains the main content. A section groups a topic and usually has a heading. An article works well for a project card that makes sense on its own.

Use one clear h1 for the page title, h2 for its main sections, and h3 for headings within those sections. Choose the heading level for the document’s structure; CSS will handle its visual size.

Follow paths and hooks

A class can be shared by many elements and is useful for styling. An id must identify one element on the page. This project also uses attributes such as data-intro so JavaScript can find specific content.

A relative path is resolved from the current page. From the portfolio’s root page, assets/cover.jpg points into the assets folder. From this course folder, ../index.html goes up one level to the portfolio.

HTML · an image
<img src="assets/cover.jpg" alt="Green and cream poster with oversized serif lettering">

Images do not have a closing tag. Their alt text describes the useful information in the image. We’ll return to this in the accessibility lesson.

Lesson 03 / 08 · CSS foundations · ~35 min

Give your page a point of view.

A few deliberate choices can give a simple page a strong personality. Learn how this portfolio uses a small color palette, two kinds of type, and plenty of space.

  • Write CSS rules
  • Understand the box model
  • Use custom properties

A selector chooses. A declaration changes.

In a CSS rule, the selector chooses the elements to style. Inside the braces, each declaration pairs a property with a value. A dot selects a class, a hash selects an ID, and an element name selects every matching element.

styles.css · a rule
.hero-intro {
  color: var(--muted);
  font-size: 16px;
  line-height: 1.65;
}

This selects elements with class="hero-intro". line-height without a unit multiplies the text size: 1.65 gives each line room to breathe. CSS comments use /* like this */.

Understand the space around a box

Every element occupies a box. Content sits in the middle, padding is space inside the border, and margin is space outside it. A border sits between the padding and margin.

CSS · a box you can experiment with
* { box-sizing: border-box; }

.note-card {
  max-width: 420px;
  padding: 24px;
  border: 1px solid #637166;
  margin: 32px auto;
}

border-box includes padding and borders in the element’s declared width, which makes sizing more predictable. max-width sets an upper limit, and horizontal auto margins can center a block when there is spare space.

Give your design a small vocabulary

The top of themes.css defines custom properties. A name beginning with -- stores a reusable value. :root makes these values available throughout the document; var() reads one.

themes.css · Parisian Gallery tokens
:root {
  --paper: #faf9f6;
  --ink: #242120;
  --muted: #66615b;
  --accent: #7b263d;
}

body {
  background: var(--paper);
  color: var(--ink);
}

Changing one token can update many elements at once. Begin with one background, one text color, and one accent. The portfolio pairs a readable sans-serif font with Georgia for expressive italic headings. You do not need a downloaded font to make the page feel personal.

Switch the whole design with configuration

In site.json, change "theme": "parisian-gallery" to "cobalt-studio", "playful-sketchbook", or "midnight-atelier". Save and refresh to see the new palette, typography, and homepage layout. The gallery, model page, and course follow the same setting.

theme.js reads this setting once per page and adds a data-theme attribute to the document. Rules in themes.css select the matching palette. Use the :root values to customize Parisian Gallery, or the matching [data-theme] block to customize another preset.

When a style seems to be ignored

CSS rules can compete. More specific selectors can win over broader ones. When importance and specificity match, the later declaration wins. In browser developer tools, inspect an element and look for crossed-out declarations to see which rule is winning.

Try one change at a time. Start with spacing, then color, then typography. A small, visible change teaches you more than replacing the whole stylesheet.

Lesson 04 / 08 · Responsive design · ~35 min

Let the layout breathe.

Your page needs to work in a narrow phone browser and on a wide desktop. Responsive design gives content rules for using the space it actually has.

  • Choose Flexbox or Grid
  • Use flexible widths
  • Test narrow screens

Start with a flexible container

A fixed width like width: 1180px can overflow a phone. This portfolio’s .wrap class combines a maximum size with space at the edges. min() uses whichever value is smaller.

styles.css · desktop container
.wrap {
  width: min(1120px, calc(100% - 80px));
  margin-inline: auto;
}

On a large screen, the content stops growing at 1120 pixels. Below that size, it uses the available width minus 80 pixels. The existing mobile rules make the side margins smaller on narrow screens.

Use Flexbox for a row

Flexbox is useful when arranging items mainly along one axis. The portfolio header puts a wordmark at one end and navigation at the other. gap adds space between items without adding it around the whole container.

CSS · simplified header
.site-header {
  display: flex;
  align-items: center;
  justify-content: space-between;
  gap: 24px;
}

Use Grid for project columns

Grid describes rows and columns. In this rule, repeat(2, ...) creates two equal columns. 1fr means one share of the available space. minmax(0, 1fr) lets a column shrink instead of being forced wider by its contents.

styles.css · project grid
.project-grid {
  display: grid;
  grid-template-columns: repeat(2, minmax(0, 1fr));
  gap: 52px 36px;
}

@media (max-width: 600px) {
  .project-grid {
    grid-template-columns: 1fr;
    gap: 38px;
  }
}

A media query applies rules when a condition is true. Here, at viewport widths of 600 pixels or less, the projects stack into one column. This is already implemented in the portfolio. Lesson 6 will give you real cards to test.

Let images fit their space

width: 100% keeps an image within its container. For a cropped project cover, object-fit: cover fills the frame while preserving the image’s proportions. Some edges may be cropped, so check the subject is still visible.

Test by narrowing the browser and by using the device toolbar in developer tools. Look for sideways scrolling, squeezed navigation, unreadably small text, and controls that are hard to tap. Also test at 200% zoom.

Lesson 05 / 08 · JavaScript & the DOM · ~35 min

Make the browser do something.

JavaScript can read the page, change its content, and react to an action. Start with one element and one small interaction.

  • Select a DOM element
  • Change textContent
  • Handle a click event

The browser turns HTML into a tree

The Document Object Model, or DOM, is the browser’s representation of your page. JavaScript can select elements from this tree. A CSS selector works here too: .class-name, #an-id, or [data-intro].

JavaScript · select and update
const introduction = document.querySelector('[data-intro]');
introduction.textContent = 'A little collection of things I make.';

const gives a name to a value. document.querySelector() returns the first matching element, or null if none exists. textContent changes its text without interpreting it as HTML.

Timing matters. The portfolio loads script.js with defer, so the HTML is parsed before the script runs. Later, its JSON request may update the introduction again. For a permanent introduction change, edit site.json.

Read the portfolio’s helper function

A function packages steps you want to reuse. This existing helper takes a selector and a value, skips empty values, and updates every matching element. querySelectorAll() gives a collection; forEach() runs a function for each item.

script.js · existing helper
const setText = (selector, value) => {
  if (!value) return;
  document.querySelectorAll(selector).forEach((node) => {
    node.textContent = value;
  });
};

// Example call:
setText('[data-name-full]', 'Isaure Leclercq');

The arrow => introduces a function. Its inputs are called parameters. A function definition does not run its body until something calls it. The footer has multiple name elements, so updating all matches keeps them consistent.

Respond to an event

A click is an event. addEventListener() registers a function to run when it happens. Use a real button for an action so keyboard users can activate it too.

HTML · add inside your Now section
<button type="button" id="idea-button">Give me a project idea</button>
<p id="idea-output" aria-live="polite">Your next idea could start here.</p>
JavaScript · append to script.js
const ideaButton = document.querySelector('#idea-button');
const ideaOutput = document.querySelector('#idea-output');

if (ideaButton && ideaOutput) {
  ideaButton.addEventListener('click', () => {
    ideaOutput.textContent = 'Design a poster for your favorite place.';
  });
}

The if checks that both elements exist. This prevents an error if the HTML is missing. aria-live="polite" helps assistive technology announce the changed message.

Open the browser’s developer tools and choose Console when something fails. An error such as “Cannot read properties of null” often means a selector did not find the element you expected.

Lesson 06 / 08 · JSON & fetch · ~40 min

One card. Many possibilities.

The project layout stays the same while your work grows. Put the content in JSON, load it with JavaScript, and let one card-building function do the repetition.

  • Write valid JSON
  • Follow a fetch request
  • Add real project cards

Separate content from layout

JSON is a text format for structured data. An object uses braces and named properties. An array uses brackets and contains a list of values. The portfolio’s projects.json is an array of project objects.

projects.json · one sample project
[
  {
    "title": "Garden notes",
    "category": "Visual identity",
    "year": "2026",
    "description": "A small identity inspired by neighborhood gardens.",
    "color": "#e4e6da",
    "mark": "G"
  }
]

This is fictional sample content to replace with your own work. JSON requires double quotes around property names and text. Separate entries with commas, but do not put a comma after the last entry. Comments are not allowed.

In this portfolio, only title is required. Optional fields include cover, coverAlt, url, and a links array. Without a cover image, the script draws a typographic placeholder using color and mark.

Load the file in the browser

fetch() starts a request and returns a promise for its response. In an async function, await pauses that function until the awaited promise settles. The rest of the page can remain responsive.

JavaScript · a standalone loading example
const loadProjects = async () => {
  try {
    const response = await fetch('projects.json');
    if (!response.ok) throw new Error('Could not load projects');

    const projects = await response.json();
    renderProjects(Array.isArray(projects) ? projects : []);
  } catch (error) {
    console.info('Project list is not available yet.', error);
    renderProjects([]);
  }
};

loadProjects();

Check response.ok because a response with an HTTP error such as 404 does not by itself reject the fetch promise. response.json() parses the response text into JavaScript data. The catch block handles request or parsing errors and shows an empty list.

Follow the data into the DOM

projects.json→fetch + parse→makeCard→page

The portfolio’s makeCard(project, isFeatured) builds an article, cover, heading, description, and links. It returns a DOM element. The script selects one featured project, then maps the remaining projects into cards. replaceChildren() inserts them into the page. If the JSON request fails, the complete collection already in the HTML remains visible.

You do not need to rewrite that function to add work. Add another object to the JSON array. The project count and empty-state message update automatically. If you add a cover, put its image file in assets/, and match the path and capitalization exactly.

Lesson 07 / 08 · Accessibility & testing · ~30 min

Good design includes people.

A portfolio should be comfortable to read and easy to use. Test the experience with different inputs, screen sizes, and ways of reading the page.

  • Test with a keyboard
  • Write useful alt text
  • Find and fix common errors

Start with the keyboard

Some visitors use a keyboard, a switch, or assistive technology instead of a mouse. Press Tab to move forward through interactive elements, Shift + Tab to move back, and Enter to follow a link or activate a focused button. Buttons also respond to the space bar.

The current portfolio includes a “Skip to content” link. It becomes visible when focused and takes you past repeated navigation. Keep it. Use links for navigation and buttons for actions, and do not remove focus outlines without replacing them.

styles.css · visible keyboard focus
a:focus-visible,
button:focus-visible {
  outline: 3px solid currentColor;
  outline-offset: 5px;
}

Describe what an image contributes

A project cover might need the description “Cream packaging with green botanical line drawings.” Writing “image” or repeating the filename tells the reader little. If an image is purely decorative, use an empty alt="" so it can be skipped.

The portfolio uses coverAlt from each project object as the cover image’s alternative text. Supply a useful description when the image communicates something about your work.

Check readability, not just aesthetics

Normal text should have at least a 4.5:1 contrast ratio against its background; large text has a 3:1 minimum under WCAG AA. Use the contrast information in browser developer tools or a contrast checker. A pretty palette does not guarantee readable text.

Also inspect at 200% zoom, use a narrow viewport, and check that long project titles wrap. Do not use color as the only way to communicate a status. A label such as “Complete” helps everyone understand the meaning.

Use the browser as a debugging tool

What you seeWhat to check
The old introductionSave site.json, refresh, and check for a JSON parsing error in Console.
No project cardsCheck that projects.json is a valid array. The empty-state fallback also appears after loading errors.
A broken imageCheck its exact path and filename. Look for a 404 response in Network.
A missing styleInspect the element and check for a competing rule or a misspelled class.
Sideways scrollingLook for fixed widths or long content that cannot wrap.

Testing is an ongoing habit. Automated tools can help, but a manual keyboard pass and a careful read catch issues a score can miss.

Lesson 08 / 08 · Git & GitHub Pages · ~30 min

From your laptop to a link.

You now have the pieces of a personal portfolio. Learn how Git records a version, GitHub stores it, and GitHub Pages makes it available on the web.

  • Understand add, commit, push
  • Configure branch publishing
  • Verify the live site

Understand the three places your code lives

Your working folder contains your current edits. Your local Git repository records saved versions called commits. The remote repository on GitHub receives commits when you push. Editing a local file alone does not update the published website.

This workspace already has the portfolio repository connected as origin, and its local main branch tracks origin/main. Before publishing, inspect what has changed:

Terminal · inspect your changes
git status
git diff

git status lists changed and new files. git diff shows changes in tracked files; newly created files need to be opened separately for review. Confirm you are in the intended repository and branch.

Save a version and send it to GitHub

For a practice project, work in your own copy or fork. Only push to this portfolio if you are authorized to update it. When you are ready to publish your reviewed changes:

Terminal · publish reviewed portfolio changes
git add index.html styles.css themes.css theme.js script.js site.json projects.json assets/
git diff --staged
git commit -m "Personalize portfolio and add projects"
git push origin main

add stages the chosen files, commit saves a local version, and push sends commits to GitHub. The example stages the portfolio files. Add any other new files you intend to publish explicitly. If GitHub asks you to authenticate, use your normal GitHub sign-in or configured Git credential flow.

Pause before the push. If Pages is already configured, pushing to its publishing branch updates the live site. Review staged files for unintended changes or private information first. If Git reports a conflict or rejects a push, resolve it before continuing; do not force-push as a shortcut.

Enable GitHub Pages

With repository admin or maintainer access, open the repository on GitHub and follow these steps. The labels below follow GitHub’s current documentation; older videos may show a different interface.

  1. Open Settings → Pages.
  2. Under Build and deployment, choose Deploy from a branch as the source.
  3. Select main and /(root), then save.
  4. Wait for the Pages deployment to finish. Check the repository’s Actions area or Pages settings if it fails.

For this repository, the published address is isaureleclercq.github.io. In your own account, a repository named YOUR-USERNAME.github.io uses that account’s root Pages address. An ordinary project repository typically lives under /REPOSITORY-NAME/, so relative file paths are useful.
